## 1. 本轮研究目标

在已经运行的商品图 V1 基础上，完善商品理解、参考图适配、专业制作决策及 Context Engineering。

当前业务具有两个目标：

**业务目标：** 提高商品图正确性、专业性及运营可接受程度，减少无效生成和返工。

**工程目标：** 基于真实业务验证 Knowledge、Rules、Skills、Workflow、Agent、Context 和 Evaluation 的实际价值，形成可迁移的 Enterprise AI 工程能力。

不重写已有商品图业务，不重新设计 Task、Review 与完整生成链路。

Agent 是否必要仍需评价。

## 3. 真实运营业务规则

本节是对 [业务基线 V0.2](../02_BUSINESS_MODELING/V1_BUSINESS_BASELINE_V0.2.md)的研究适用性说明，不建立第二份业务规范。下列已确认事项为 **OPERATOR_CONFIRMED（经用户转述）/ DECIDED**，不等于已由代码实现或独立完成事实认证。

### 已确认

- **只有 Quick 与 Listing 两种模式。**Quick-A / Quick-B 是 Quick 的两个业务子场景，不是三个独立业务产品，也不要求三者采用相同的 Planning / Agent 流程。
- **Quick 是图片驱动的输入模式。**运营提供实际销售商品图片、参考营销图片及可选整体/逐图制作要求；不要求手动输入 Listing、产品描述或卖点资料。商品信息由图片提供，可选制作要求不改变这一前提；Quick 不增加强制独立 AI Planning。
- **Quick-A｜同款同外观再设计：**实际商品与参考商品外观一致，具体型号/变体适用性由业务确认。保留真实商品外观和适用参数、卖点与信息，调整构图、排版、风格、语言或地区表达；不能因再设计而改坏商品信息。
- **Quick-B｜适用信息沿用与主体替换：**实际商品和参考商品外观不同，但运营确认本次使用的尺寸、规格、卖点适用于目标商品。必须使用实际销售商品替换参考商品主体，实际商品原图决定最终外观；允许沿用经确认适用的信息及设计表达，不得混合两款商品结构。**外观不同本身不表示参考图不适用。**
- **来源与权利边界：**不能继续假设“所有参考图信息都不能继承”。Quick-A 与经确认的 Quick-B 可沿用适用信息，但不能自动转移错误型号/变体、其他配置、第三方品牌或无权使用的素材。运营确认适用不等于独立规格核验，也不等于平台/版权认证；渠道和地区要求仍须实际核对。
- **Listing 是资料驱动模式。**运营主动提供商品图片、参考图片及 Listing、产品描述/卖点等文字商品信息，模型基于这些资料理解和规划，运营确认后制作；不能用只传图片替代该业务输入。具体文本框是否分别必填仍按 V0.2 的边界核对，不在研究文档新增字段校验规则。**Listing 参考图是否始终同款为 UNKNOWN**，不得自动套用 Quick-A / Quick-B 的信息沿用规则。
- **尺寸图专项前提：**只有运营提供已经标注目标商品真实尺寸的白底素材，才存在本次尺寸图需求；未提供表示本次不需要。不得从参考数字、比例或模型推测填数，也不为补齐图包自动生成。此专项限制不因 Quick-A / Quick-B 可沿用其他适用信息而取消。
- **参考选择习惯：**运营一定会参考视觉风格和设计表达，通常也已考虑卖点相同或相近；卖点不同、主要借鉴风格的情况较少。核心表达确实不适用时，默认建议运营更换参考，最终由运营决定；不能仅因 Quick-B 外观不同就建议换图。
- **人工责任：**运营最终接受图片。既有用户转述还记录，很多设计分析依靠 GPT、运营通常缺少系统性专业设计知识；本轮未独立访谈或测评，不将此描述推广为所有运营的能力结论。

### 尚未确认

- 专业商品图设计的完整目标 SOP。
- Quick-B 如何表达和核对“这些规格/卖点对目标商品适用”，以及信息冲突的处置边界。
- Listing 参考图与目标商品的实际关系及其信息确认权限。
- 不同平台规则的实际维护责任及具体适用要求。
- 运营接受或拒绝图片的具体专业理由。
- 哪些设计方法可以稳定改善实际成图质量。

不得将 AI 自行推导的设计原则直接升级为真实人工 SOP；业务确认、工程实现与真实效果分别记录。

## 4. 业务能力拆解与 Agent 适配状态

“当前已有机制”沿用既有源码/Evidence 调查；三类场景列描述待研究的业务判断，不宣称新增实现，也不要求新增统一前置 Planning。

| SOP / 能力 | 当前已有机制 | Quick-A 研究判断 | Quick-B 研究判断 | Listing 研究判断 | 技术适配状态 |
|---|---|---|---|---|---|
| S1 商品理解 | Listing 候选理解、卖点和不确定性；Quick 由图像请求隐含理解 | 识别目标商品、适用参考信息及需保留内容 | 区分目标外观与运营确认适用的参考规格，暴露 SKU/变体冲突 | 基于手动提交的资料和图片区分事实、声称与未知 | 条件性候选；无自动事实认证结论 |
| S2 参考图理解 | 多模态模型；Listing 保存独立参考理解 | 识别有效信息、视觉表达及差异化空间 | 识别参考主体、适用信息与设计表达，不能与目标外观混同 | 识别参考表达及来源；同款关系 UNKNOWN | 优先保留 Model-only 基线，增益待验证 |

| S4 地区与平台规则 | 运营文本、固定 Prompt | 核对再设计及语言/地区表达的适用要求 | 核对替换后的宣称、权利及渠道要求 | 核对资料、计划和发布场景的实际要求 | 规则来源/版本及硬约束待研究 |
| S5 专业制作方案决策 | Listing 显式逐图计划；Quick 隐含制作决策 | 保留有效信息并形成有意义的设计变化 | 替换为目标主体，保持适用信息，避免混合结构 | 基于商品信息及确认方向选择卖点和设计方案 | 重点研究；不预定 Agent、工具或 Skills |
| S6 Context Engineering | 确定性素材绑定、请求组装、版本记录 | 区分外观依据、适用信息与设计要求 | 明确目标外观、适用参考信息及替换边界 | 组织手动资料、理解、确认计划及本次修改 | 确定性绑定为既有机制，增强方式待评价 |

Review / Evaluation 贯穿全部业务环节，不提前定义为独立 Agent。

上表是 **PROPOSED 的能力分析与技术适配研究**，并非六个已批准实现模块。Agent 数量、工具列表、Knowledge Schema、Skills 加载方式、固定 Agent Workflow 和新代码模块均未确定。

## 5. 已有重要实验与失败证据

### E1｜尺寸图依据问题

曾出现没有可追踪自家商品尺寸依据、却生成具体尺寸数字的情况。

后续运营业务澄清：真实尺寸图需要已标注尺寸的专用白底素材，未提供则不需要制作。

**待核对：** E1 是否属于测试输入偏离真实 SOP，以及现有图位启用规则是否需要调整。

不得直接认定模型复制了参考图尺寸。

### E2｜Listing 理解、规划和生成闭环

已经观察到模型可以记录商品不确定性，将确认后的计划传入 Generation，并绑定具体 Pass 版本。

但不能证明最终图片全部专业正确，也不能证明运营接受理由已被记录。

### E3｜参考图理解失败

实际参考图强调手持、尺寸与重量，模型却误读为两种握法与按钮特写。

错误理解进入了后续生成 Context。

这是 **OBSERVED 的语义误读与传播**，但最终质量影响和根因仍待验证。

### E4｜修改与反馈证据

已找到父子 Run 关联和反馈进入 Context 的记录，但调查中的对应样本属于离线 Mock。

不能用它证明真实图片编辑效果。

### 2026-10-27 A/B 方案及成图实验｜业务适用性限制

依据 [V0.2 的历史实验记录](../02_BUSINESS_MODELING/V1_BUSINESS_BASELINE_V0.2.md#82-observed--historical有时间与证据边界)及本次用户确认：共同提示词以参考商品信息不能沿用为前提，将两组目标收缩为外观细节展示。该前提不符合真实 Quick-A / Quick-B 的适用信息沿用业务，不能据此充分评价真实 Quick 的成图效果或 S3/S5 SOP 的增益。

- 原始实验 Evidence、图片、请求、方案与输出全部保留，不改写或重新标成生产验收。
- 已有排版、引线、商品印字失真等技术观察可以保留，但不能自动解释为符合真实 Quick 业务的效果验证。
- **SOP / Agent 的增量价值仍为 UNKNOWN。**实验执行或出图成功不等于 Agent 增益已验证。
- 本轮只对齐文档适用性，未读取原始 Runtime、核对完整实验条件或执行新对照。

### C02｜历史 Model-only 与 Skill 对照

2026-10-13，旧 `tiktok-jp-image-tool` 中进行了三张参考图、两组条件、六次真实模型调用的比较。

Skill 组增加了 Token 和耗时；没有得到经过正式人工评价证明的明显识别质量收益。

**研究启示：** 基础视觉理解保持 Model-first，不默认加载通用分析 Skill。

该实验不是当前商品图业务规划或最终生图质量的验证结论。小样本“未证明明显收益”也不表示 Skills 在所有场景无用；特定专业方法是否有效仍需符合业务前提的对照评价。

## 7. 当前优先研究的业务问题

### Priority A｜S3 参考图适配

需要回答：

- 如何准确理解运营已经初筛过的参考图？
- 怎样判断参考卖点与自家商品卖点是否真正匹配？
- 什么情况下适合借鉴，什么情况下应建议换图？
- Quick-A / Quick-B 哪些参考信息可沿用，哪些结构、品牌及不适用事实必须排除？
- 怎样识别 Quick-B 的主体替换需求，避免把外观不同误判为参考不适用？
- 是否需要外部专业知识、动态查证或人工复核？

### Priority B｜S5 专业制作方案决策

需要回答：

- Quick 的隐含制作决策与 Listing 的显式 Planning 分别缺少哪些专业判断？
- 制作方法的可靠来源是什么？
- 什么情况下需要查找或加载某种专业方法？
- 如何在保留适用信息的同时完成 Quick-A 再设计、Quick-B 主体替换；Listing 又需哪些不同判断？
- 怎样评价专业方案是否优于原生模型？

S1 商品事实和 S4 渠道规则为这两项提供约束。

S2 先保持模型原生理解基线；S6 Context 优化应根据实际决策结果开展。
