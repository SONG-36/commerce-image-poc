## 0. 执行摘要

本轮聚焦一个问题：**怎样让 AI 为卖点图选择更有依据、更可执行的专业视觉表达方法，并证明这些方法是否改善制作质量？**

现阶段的候选结论：

1. **先区分问题类别**：商品事实/权限错误是业务 Rules 问题；参考误读是 S2/S3 问题；专业设计取舍才是 S5 问题；成图失真还可能是图像模型或编辑工具问题。不能把所有失败归因为“缺少 Skill/Agent”。
2. **原生模型是基线**：在已确认商品事实、参考信息、图位目标和业务规则前提下，先评估原生多模态模型的专业制作决策表现。
3. **专业 Knowledge 是候选增益**：本轮形成六张卖点图设计方法卡（K01–K06），它们是**候选启发式**，不是经过运营验证的通用规范，更不是对模型的商品事实授权。
4. **先评价方案，再评价成图**：先建立事实硬约束与五维 S5 方案评分；之后才做少量实际图片生成与运营返工评价。
5. **暂不批准 Skill/Agent**：只有证明专业方法本身有收益，才研究固定 Context、知识检索或 Skill 包装；只有出现确实需要动态查证、多步工具决策的任务，才考虑受约束的 Agent。

**证据状态提醒**：本文件综合本次对话中的专业资料研究与既有 Codex 只读调查。对话中提及的外部来源名称、平台规则和部分研究结论，**本次文档制作没有重新取得原始网页并逐条校验**；外部资料标为 `SOURCE-LEAD / VERIFY`，不能据此宣称 2026 年 10 月的当前平台政策已独立核实。

## 1. 研究前提与证据分层

### 1.1 业务权威边界（DECIDED；以现有 Business Baseline/Workflow 为准）

| 场景 | 商品外观依据 | 商品信息权限 | 设计任务 | 人工确认 |
| --- | --- | --- | --- | --- |
| Quick-A｜同款快速改版 | 实际售卖商品原图 | 同款参考图中适用于当前商品/变体的信息可沿用 | 选取适用卖点、差异化再设计 | 正常任务不强制独立 Planning；最终运营 Pass |
| Quick-B｜换主体快速改版 | **实际售卖商品原图，必须替换参考商品所有相关主体** | 经运营确认适用于目标商品的参考参数、功能、卖点可沿用 | 完整换主体、调整特写/引线/布局，保留适用营销意义 | 正常任务不强制独立 Planning；最终运营 Pass |
| Listing｜商品资料制图 | 实际售卖商品原图 | **运营手动提供的 Listing/描述/卖点等是主要商品事实依据**；参考图额外宣称必须核对 | 商品理解、参考适配、逐图创意规划 | **运营先确认计划**，再生成，最终运营 Pass |

跨场景约束：

- 运营明确要求必保留的信息，不得未经确认擅自删除；允许针对图位聚焦部分**适用**卖点，但不改变其事实含义。
- 商品原图决定外观，但不自动验证全部隐藏功能或规格；文字与图片明显冲突应显式交运营确认。**看不见不等于不存在**。
- **尺寸图只有在运营提供“已标注目标商品真实尺寸的白底专项素材”时才制作**；模型、参考图或设计知识不得补造尺寸。
- 平台/地区/图位规则必须按实际适用范围核对；“重新设计”不等于自动获得素材授权或合规保证。
- 三种场景均由运营最终审核认可版本，生成成功不等于 Pass。

### 1.2 现有工程观察（OBSERVED / HISTORICAL；来自最近 Codex 只读报告）

| 观察 | 涉及能力 | 不应得出的过度结论 |
| --- | --- | --- |
| Quick V1 Prompt 仍禁止从参考继承功能/尺寸等，与已确认 Quick-A/B 权限不一致 | **S3 / Rules** | 不能直接归结为“缺乏设计 Knowledge” |
| Quick V1 尚未把 A/B 作为独立业务策略执行；视觉设计由生成模型隐含决定 | S3 / S5 | 不等于当前模型一定无法完成任务 |
| 曾在缺少真实尺寸专项素材的情况下生成带新尺寸数字的图 | **硬性前置规则 / S6 / 生成执行** | 不能确定数字究竟来自模型估测、参考误读或其他过程 |
| Listing 已能输出 `goal / selling_points / design / scene_style / risks`；计划能传入生成 | S5 / S6 | 结构非空不等于设计专业、事实正确 |
| 一例 Listing 的参考营销图被误读，错误理解进入后续计划 | **S2 → S3/S5** | 不能只根据最终成图归因于 S5 |
| 已查看案例缺乏结构化接受/拒绝原因和专业质量评分 | **Evaluation / Evidence** | 没有 Pass 不等于运营明确拒绝 |
| 正式请求链未见专业知识检索、制图 Skill 或自主 Agent | AI Suitability | 不代表这些技术必然有益或无益 |

**归因原则**：把 `事实来源 → 参考理解 → 制作决策 → Context 传递 → 图像执行 → 人工评价` 当作不同可观察环节。未取得对应证据时标记 `UNKNOWN`。

- `DECIDED`：经业务确认的约束；不能由模型随意改变。
- `OBSERVED`：已有代码、请求或真实运行记录直接支持的事实；保留时间/版本边界。
- `RESEARCH-LEAD`：对话中引用的外部研究/官方资料方向，原始出处、日期、适用范围尚待逐项复核。
- `PROPOSED`：本文件提出的专业知识卡、评价标准或实验设计。
- `UNKNOWN`：当前尚缺真实运营、模型或来源证据。

## 3. S5 的候选专业制作决策方法

> **目标**：从泛泛的“做得更高级”变成“针对本商品、图位和真实卖点，选择有理由、可执行的视觉表达”。

### 3.1 五个业务问题（PROPOSED，不等于五次模型调用）

1. **用户需要理解什么？** 明确这一图位要回答的购买疑问/核心价值，不混淆营销目标与视觉风格。
2. **有什么真实依据？** 整理已允许使用的卖点及目标 SKU 素材；标记未知、冲突、必保留约束。
3. **什么方法最合适？** 根据卖点性质选择局部结构、双状态、场景、比例或其他表达；说明为什么不是其他方法。
4. **怎样组织这一张图？** 明确主体、标题、信息层级、特写与箭头关系、参考风格迁移和不可改动元素。
5. **怎样确认方案能够制作？** 依据真实图片/文案检查是否会虚构结构、参数、角度、包装或性能；不满足时调整方案或请求运营补资料。

**预期最小结果**：一份可供运营判断的**单图制作方向**，而不是一份长篇设计理论说明。Listing 可以成为显式 Planning；Quick-A/B 不因此新增强制 Planning Gate。

### 3.2 卖点到视觉方法的候选映射

| 卖点类型 | 候选表现 | 最重要的依据问题 | 常见失败 |
| --- | --- | --- | --- |
| 可见硬件结构/接口/按钮 | 主体 + 真实局部特写 + 指向标注（K01） | 目标商品素材能否明确定位该部件？ | 指错部位、生成不存在的接口 |
| 双模式/多状态/可变形 | 真实状态并列或转换关系（K02） | 是否确认具有该状态且素材可支持？ | 虚构第二形态、错误转换机构 |
| 与使用环境相关的功能 | 相容的使用场景 + 一项重点信息（K03） | 场景会否暗示未证实能力或效果？ | 功效夸大、错误操作方式 |
| 轻量/便携/舒适等抽象价值 | 可信参照 + 真实结构/使用说明（K04） | 有无能支持描述的事实与合适参照？ | 编造重量、比较基线或效果 |
| 多卖点、信息拥挤 | 优先级选择与分组（K05） | 哪些是图位重点，哪些由运营要求必保留？ | 文案堆叠、丢失必保留信息 |
| 移动端缩略观看 | 对比、文字数量与缩小预览检查（K06） | 图片缩小时还能识别核心信息吗？ | 小字不可读、弱对比 |

## 4. 六张候选专业知识卡（K01–K06）

**所有知识卡状态：`PROPOSED / NOT OPERATOR VALIDATED`。** 它们是 S5 决策辅助素材，不是运行时 Skill、确定性规则或对当前商品事实的授权。

### K01｜局部特写与功能标注

- **适用触发**：卖点是按钮、接口、接头、开关、纹理、附件安装位等可见部件。
- **必要输入**：真实商品图中对应部件的清晰视角；可使用的功能说明。
- **制作方法**：保持商品整体可识别；把对应部件以真实特写或裁切区域展示；引线与文字一一对应；避免信息卡遮挡关键结构。
- **不适用 / 异常**：真实素材无该角度、部件被遮挡、商品说明与外观冲突；应补素材或转换图位表达，不能凭空生成结构。
- **审核要点**：所有箭头/引线所指部件真实存在；局部图与商品主体属于同一 SKU；文字与结构匹配。
- **外部来源方向**：Baymard 商品细节图、Shopify 细节摄影、视觉层级设计资料（待复核原文）。

### K02｜多形态与状态展示

- **适用触发**：商品有已确认的两种/多种工作状态、形态或操作方式。
- **必要输入**：对应功能的商品依据、能证明或合理支持各状态的图片/技术资料。
- **制作方法**：用并列状态、对应视角或转换关系展示差异；视觉联系清楚但不夸大实际变形路径。
- **不适用 / 异常**：仅凭参考图存在另一形态，或缺目标商品的关键结构证明；不得生成看似真实但无依据的转换部件。
- **审核要点**：状态数量、结构、关系和文案均受当前商品资料支持。
- **示例限定**：Listing 电动螺丝刀若已确认有 `2WAY` 功能，可考虑直柄/枪柄两状态；是否具备可用真实素材仍应核实。

### K03｜场景化利益表达

- **适用触发**：卖点与使用条件、环境、场合有直接联系，单独主体不足以解释价值。
- **必要输入**：商品真实用途、场景限制、适用人群或环境的可靠资料。
- **制作方法**：展示目标商品在合理场景中的使用关系；保持主体识别度和一项清晰价值主张。
- **不适用 / 异常**：场景暗示未经证实的强度、速度、适用材质、人群或结果；不能仅凭参考图迁移高风险使用情境。
- **审核要点**：操作方式、接触部件、产品尺寸、环境和效果均没有违反实际商品事实。

### K04｜抽象卖点的可理解表达

- **适用触发**：轻巧、便携、易操作、舒适、耐用等用户价值无法仅由产品白底图直接说明。
- **必要输入**：可引用的客观事实、尺寸/重量或经确认的定性宣称；可使用的真实比例参照。
- **制作方法**：选择能让用户理解的场景、真实比例关系、细节或简短说明；区分客观参数与主观感受。
- **不适用 / 异常**：不得将“轻巧”自行写成具体重量、将“耐用”写成未经证实寿命、将“舒适”作为可量化医学/功效结论。
- **审核要点**：信息层级清楚、证明方式与实际依据强度匹配。

### K05｜多卖点的优先级与信息层级

- **适用触发**：参考图/商品资料有多个可用卖点，当前单图空间或图位目标不宜同时强调全部内容。
- **必要输入**：已确认可用卖点、运营必保留内容、当前图位、参考营销意图。
- **制作方法**：明确一个视觉主目标；其他信息按重要性分组、弱化或分配给其他图位；由大小、对比、空间关系建立阅读顺序。
- **业务权限**：Quick-A/B 允许聚焦部分适用卖点；Listing 的卖点选择需受商品资料和运营确认计划约束。三者都不能擅自删必保留内容。
- **不适用 / 异常**：如果参考图核心意图不再成立，应说明原因而非伪造新的商品价值。
- **审核要点**：第一眼是否读到本图核心内容；辅助信息是否服务主目标；是否存在遗漏的硬约束。

### K06｜移动端可读性

- **适用触发**：商品图可能以手机商品详情页缩略图/画廊图方式浏览。
- **必要输入**：目标展示环境（如未知则标明假设）、实际文案及图像尺寸。
- **制作方法**：控制低价值小字；使主标题和主要商品保持可识别；检查缩小后的字形、对比、信息密度和遮挡。
- **不适用 / 异常**：不可把某一对比度数值自动当成所有平台图片的强制要求；不同语言和渠道需分别检查。
- **审核要点**：缩小预览仍能判断商品和核心功能；重要文字是否清楚；不因提高可读性而改写宣称。

### 4.1 方法卡的使用边界

- **知识卡指导“怎样表达”，不指导“哪些未经证实的事实可以成立”。**
- 不应把所有 K01–K06 一次性加载；只考虑与当前图位和目标卖点相关的卡。
- 若基础模型已经稳定给出同样或更好的设计决策，额外加载知识没有当然的收益。
- 不以“输出更多设计术语、解释更长”作为知识有效的标准。

## 5. S5 方案评价方法 V0.1（PROPOSED）

### 5.1 两层评价，不能互相抵消

**第一层：业务硬约束（Gate / Pass–Fail–Needs Confirmation / N/A）**

| 检查项 | 方案层检查重点 | 成图层补充检查 |
| --- | --- | --- |
| G1 商品身份 / 外观 | 方案是否明确以实际商品素材为准 | 商品外观、结构、标识与真实 SKU 是否一致 |
| G2 宣称依据 | 使用的参数、功能和卖点是否有允许的来源；争议是否提示 | 成图是否出现未经允许的新文字、数字、功效 |
| G3 Quick-B 完整换主体（仅 Quick-B） | 主视觉、局部特写、场景等替换范围是否覆盖 | **所有相关参考主体是否真的替换，是否出现混合结构** |
| G4 运营必保留内容 | 是否明确完整保留或已取得变更批准 | 输出是否实际呈现 |
| G5 信息冲突 | 图片/Listing/参考之间明显冲突是否已处理 | 不应因生图而掩盖或引入冲突 |
| G6 尺寸图专项（仅尺寸图） | 是否存在真实尺寸标注白底素材；否则不允许规划尺寸图 | 数值、单位、标注对应位置是否正确 |
| G7 平台/地区/图位适用 | 已指明的规则是否核对来源与适用范围 | 文案、主图/附图表达是否与有效规则一致 |

- 对**未解决的关键事实冲突**，标记 `NEEDS_CONFIRMATION`，不能当作通过。
- 对不适用当前任务的项标记 `N/A`，不伪造失败。
- **Gate 失败不能用专业设计高分补偿**；自动检查只提供辅助，最终由运营负责验收。

**第二层：S5 专业制作方案质量（每项 0–3 分，总分 0–15）**

| 维度 | 主要问题 | 0 分 | 1 分 | 2 分 | 3 分 |
| --- | --- | --- | --- | --- | --- |
| Q1 表达目标 | 是否回答主要购买疑问？ | 无明确目标 | 目标含混或偏题 | 基本清楚 | 重点明确、与图位契合 |
| Q2 视觉方法适配 | 方法是否匹配卖点性质？ | 无可用方法 | 方法明显不适合 | 基本适合但需调整 | 方法有充分选择理由 |
| Q3 信息层级 | 商品、卖点、辅助说明是否组织合理？ | 难以理解 | 主次混乱 | 基本清楚 | 主次鲜明、信息互相支持 |
| Q4 参考图利用 | 是否正确理解并转化参考表达？ | 忽略或误解 | 机械照搬/偏离严重 | 基本借鉴 | 适用、差异化且有理由 |
| Q5 制作可执行性 | 素材能否支撑计划？ | 明显需虚构 | 多项缺失 | 大体可执行、需少量补充 | 依据充分、可直接制作 |

评分说明：`0=缺失或明显不适用；1=存在重大问题；2=基本可用但需修改；3=判断清楚且依据充分`。**目前不设擅自的“合格分数线”**。记录每项理由、引用事实和待修改项；最好由至少两名评审独立评分并记录分歧。首次由一名运营试用也可，但需明确其证据局限。

### 5.2 区分“方案评价”和“实际成图评价”

- **方案层**：问“为什么这样设计、材料是否支持、是否有明确画面关系”；不能因为方案写得专业就认定成图成功。
- **成图层**：检查真实商品保真、文案准确、引线位置、实际文字可读性、平台适配、运营返工次数和最终 Pass。
- Quick-B 尤其需要分别保留“替换范围规划正确”与“实际图片完整替换”的证据。
- `Review = Pass` 没有拒绝理由，并不足以支持 Knowledge 的稳定增益分析。

### 5.3 最小人工评价记录建议（尚非数据库契约）

记录：`case_id / mode / slot / sku / source_snapshot / plan_variant / reviewer / gate_items / Q1..Q5 / reasons / proposed_changes / review_time / model_id / prompt_or_knowledge_version`。后续真正实施时再定字段、隐私边界、版本与持久化格式。

## 6. 先做 Listing“方案层 A/B”，不急于生图

### 6.1 研究问题与假设

- **H0（保守假设）**：在相同、已核实的输入下，添加 K01–K06 中适用的方法卡不会稳定改善 S5 方案质量。
- **H1（候选假设）**：添加**少量、与本图直接有关且经人工审核**的专业方法卡，能够提高具体制作决策的依据充分性、参考适配和可执行性。
- **实验目标**：测试**知识内容的增益**，不是提前证明 Skill、RAG 或 Agent 更好。

### 6.2 样本选择与输入前置条件

初始案例候选：已有 **Listing 电动螺丝刀**真实任务中的一张卖点图。

但历史调查发现该案例的参考图理解曾不准确。因此，实验前必须先由运营/审核人确认以下共同输入：

1. 当前实际商品 SKU 和商品原图；
2. 可使用的 Listing 事实/卖点及其具体出处；
3. **人工纠正且确认**的参考图内容理解；
4. 当前图位目标、必保留要求、适用市场和展示条件；
5. 已知冲突或素材不足的处理结果。

如果这些输入无法确认，**不应直接开展 S5 A/B**；否则可能混入 S2 错误。

### 6.3 两组设计与控制变量

| 项目 | A：Model-only 基线 | B：Model + Knowledge |
| --- | --- | --- |
| 商品与参考输入 | **完全相同**且先行确认 | 与 A 相同 |
| 模型、版本与参数 | 固定记录 | 与 A 相同 |
| 基本业务 Rules | 相同 | 与 A 相同 |
| 规划任务/格式要求 | 相同 | 与 A 相同 |
| 唯一研究变量 | 无额外设计方法卡 | 注入与当前卖点图有关的**少量 K 卡** |
| 输出 | 一份制作方案，不生成图片 | 一份制作方案，不生成图片 |
| 评价 | 相同 Gate 和 Q1–Q5 | 相同 Gate 和 Q1–Q5 |

执行细则：

- 在执行前固定模型、提示词、卡片版本和评价标准，保存原始请求/响应、Usage 和耗时。
- 运营盲评，避免因知道“加了知识”而偏袒 B；最好两个评审独立评价。
- 记录**具体设计决策差异**，不能仅看评分总分或文本长短。
- 最初单对 A/B 仅用于流程试跑与发现明显缺陷，**不能证明稳定增益或统计显著性**。
- 单对实验若要执行，需单独授权至多两次 Planning 调用；**不自动生成图片、不重试、不追加批量运行**。

### 6.4 何时进入下一步

1. 若 B 未形成可评价的具体改善，先修改知识卡或停止该知识路线，不急于封装 Skill。
2. 若 B 在多案例、受控条件下重复提高专业方案质量，再研究这种知识是直接注入 Context、按需检索，还是封装 Skill 更有效。
3. 若方案层有收益但成图表现不改善，须重新调查图像生成模型、工具执行或图像质量检查，不把问题简单归因于“需要 Agent”。
4. 若出现真实的跨来源查证、工具选择与多步反馈需求，再进入 Agent 动态决策的独立验证。

## 7. Rules / Knowledge / Skills / Agent 适配初判

| 内容 / 需求 | 初步适配 | 依据与限制 | 决策状态 |
| --- | --- | --- | --- |
| Quick-A/B/Listing 的事实权限和模式声明 | **确定性 Rules** | 已获业务确认；不应让模型自行重定权限 | `PROPOSED IMPLEMENTATION, BUSINESS DECIDED` |
| 尺寸图真实标注素材前置条件 | **确定性 Rules** | 明确可检查；缺资料就不制作 | `PROPOSED IMPLEMENTATION, BUSINESS DECIDED` |
| S1/S2 原始理解与卖点提取 | **Model-first** | 当前已有能力，准确性与来源归属仍需评估 | `CANDIDATE` |
| 卖点视觉方法 K01–K06 | **少量 Knowledge 候选** | 需核实来源、运营审核和对照结果 | `PROPOSED` |
| 平台/地区规范 | **带来源/日期/范围的规则查询或知识资产** | 文件间可能存在适用条件差异；当前不能硬编码未核实结论 | `OPEN` |
| 专业制作 Skill | **暂缓** | 先验证方法有效，再判断封装和加载方式是否增益 | `OPEN` |
| 局部特写、抠图、合成、可读性检查 | **专业 Tools 候选** | 只有在模型执行/检验不足时研究，不能以工具替代商品事实 | `OPEN` |
| 动态资料查证、多步工具选择、自主修复 | **受约束 Agent 候选** | 当前未证明必要性，必须保留人工权限 | `OPEN` |

**不建议当前建立“大而全的商品图 Agent”**；也不建议把每个知识卡变成一个 Skill，更不应该因为有 `goal/design` 字段就认定 S5 已验证成功。

## 8. 适用于 Quick-A / Quick-B / Listing 的共同与差异

| S5 问题 | Quick-A | Quick-B | Listing |
| --- | --- | --- | --- |
| 最先约束的事实 | 同款外观及适用参考信息 | **目标外观 + 已确认适用的营销信息** | 运营提交的商品事实/卖点 |
| 制作决策目标 | 同款商品差异化改版 | **全范围主体替换后重新组织版式** | 根据商品信息形成逐图创意规划 |
| K01–K06 的角色 | 为卖点取舍和视觉调整提供方法 | 为新主体特写、引线、版式适配提供方法 | 为卖点分配和方案质量提供方法 |
| 必须警惕 | 意义失真、外观被重造 | 原参考商品残留、混合外观 | 参考误读、无依据额外卖点 |
| 是否新增人工规划 Gate | 不因此新增 | 不因此新增 | 保留现有运营计划确认 |
| 有效性评价 | 差异化与事实保真 | **主体完整替换**与设计质量分开评价 | 方案专业度与后续成图分开评价 |

**原则**：可以共享知识内容，不意味着三个场景采用同一份 Prompt、相同的信息权限、同一个强制 Planning 流程，或立即抽成同一后端服务。

## 9. 来源核查与知识卡晋级流程

### 9.1 外部来源待核查登记

| ID | 来源方向 | 需要补齐的最低证据 | 目前是否允许称为正式知识规则 |
| --- | --- | --- | --- |
| SRC-01 | Baymard 商品图片 UX | 原始文章标题、URL、日期、具体方法/研究语境 | 否 |
| SRC-02 | NN/g 视觉层级 | 原始文章/研究、核心定义、适用范围 | 否 |
| SRC-03 | Shopify 商品摄影 | 官方文章 URL、日期、分类及样例 | 否 |
| SRC-04 | Amazon 当前站点/图位图像规则 | 站点、品类、主图/附图、原文与版本 | 否 |
| SRC-05 | TikTok Shop US / JP 图片规则 | 地区、商品图与广告图类型、版本、冲突解释 | 否 |
| SRC-06 | FTC 广告宣称依据 | 官方原文、适用语境、具体主张类别 | 否 |
| SRC-07 | WCAG 对比度 | W3C 原文、条件、适用范围及非电商强制性质 | 否 |
| SRC-08 | 视觉注意/信息密度实验 | 原论文、样本/任务/实验条件及可外推程度 | 否 |
| SRC-09 | Temu 相关平台规范 | 可验证官方政策与图位定义 | 否（`UNKNOWN`） |

> 在未补齐上述资料前，不能将本轮来源方向作为具有权威效力的 Knowledge 或 Rules 直接注入生产链路。特别是平台政策必须重新核对当前有效版本。

### 9.2 从研究卡片升级为可运行知识的条件

1. **来源核实**：具体依据可回查；属于专业启发式还是平台硬规则有明确区分。
2. **业务审核**：运营确认方法有用且不违背商品事实、当前图位或品牌要求。
3. **适用条件**：注明适用卖点、素材前置条件、禁用条件和不确定情况。
4. **可评价**：能判断方案是否使用了该方法，以及使用后是否改善了可执行性/效果。
5. **受控验证**：与 Model-only 基线比较，证明至少在目标样本上有可重复的正面作用。
6. **再决定载体**：选择少量 Context、可检索 Knowledge、Skill 或工具，而不是从技术名称倒推需求。

## 10. 未决问题与下一轮研究任务

### 10.1 仍为 UNKNOWN

- 六张 K 卡的哪些方法能在真实运营场景显著改善方案质量，改善幅度多大。
- 不同商品品类、站点和语言对布局方法的具体影响。
- 原生模型是否已经稳定具备上述设计判断，是否存在知识加载的负收益。
- Quick-A/B 经业务确认的真实样本和运营拒绝原因是否足够支持独立评价。
- Listing 电动螺丝刀参考理解错误被纠正后，S5 制作方案表现怎样。
- 是否需要引入确定性编辑/排版工具；是否有必须由 Agent 动态调度的专业任务。

### 10.2 推荐下一步（按先后，不构成执行授权）

1. **人工审阅本文**：确认 K01–K06 是否贴近运营实际的卖点图制作方法；删掉过于宽泛或不适用的内容。
2. **回查来源**：优先核对正式设计研究和所选平台/地区/图位官方规则，补原文与版本；不要把平台政策直接混入设计启发式。
3. **固定一个 Listing 案例输入**：完成商品事实、参考理解和卖点依据的人工确认。
4. **仅方案层 A/B**：单独批准最多两次 Planning 调用；无图片生成、无自动重试。
5. **评价并决策**：根据理由和可执行差异，决定扩样、修订知识卡或停用方法。
6. **进入 04 架构适配决策**：在实证结果基础上比较固定 Context、检索、Skill 与 Agent。

### 10.3 当前明确不做

- 不开发生产级 RAG、Skills、Agent、自动修复或通用多模态编排框架。
- 不在没有真实素材的情况下生成尺寸数据或商品结构。
- 不将之前参考误读的 Listing 计划直接当作专业方法增益样本。
- 不把已有图片生成成功、字段非空或运营未拒绝当成专业质量通过。
- 不修改任何代码、Prompt、数据库、Runtime、Pilot 或部署配置。
