## 1. 业务目标与 V1 边界

V1 面向运营已有商品素材及参考营销图，目标是：**正确呈现实际售卖商品，保留有依据且适用于该商品的信息，按参考的视觉表达进行制作或再设计，支持逐图生成、审核、修改及导出。**

V1 只有**两种使用模式**，不是三个独立产品：

1. **Quick｜快速生图（图片驱动）：**运营提供实际商品图片和与目标图位对应的参考营销图，**不要求手动输入 Listing、产品描述或卖点文本**。根据商品与参考的关系，包含 **Quick-A 同款同外观**和 **Quick-B 同规格/卖点但外观不同**两个业务子场景（详见 §3.1）。原始参考图除设计方式外，也可能承载适用于实际商品的参数和卖点。
2. **Listing｜带商品信息生图（资料驱动）：**运营在商品原图、参考图外，**主动输入商品信息**（Listing、商品描述、卖点等），由 AI 进行商品与参考理解、逐图规划，运营确认后再生成。不能用“只传两张图”替代这一模式的业务输入。

两种模式交付的都是可逐图审核的商品图片，复用现有生成、版本、Review 和导出体验；但**商品信息来源及制作判断不应强制采用同一套规则**。Listing 参考图是否与目标商品同款，**此次未确认**，不能直接套用 Quick 的前提。

本 V1 不主动收集社媒/评论、研究消费者需求、制定完整营销战略，也不预设 Knowledge、Skills 或 Agent 必须实施。当前参考图主要由运营选择：运营**一定会参考其风格**，通常也事先考虑卖点相同或相近；仅为了视觉风格而选卖点不匹配的参考图属于少数情况（`OPERATOR_CONFIRMED`）。

### 2.1 三种不同的“依据”

- **外观依据（Visual Truth）：**以**实际商品原图**为准。Quick-B 即使参考图的参数可用，也不能把参考中的另一种外壳、按钮、连接件或品牌主体留在结果中。
- **商品信息依据（Claim / Specification）：**Quick-A 可使用适用于该同款商品的已有参考信息；Quick-B 可沿用**运营确认对目标商品同样成立**的规格、尺寸、功能与卖点。**同外观不自动证明全部参数真实；同规格也不等于同外观、同包装或同配件**。Listing 主要依据运营手动提交的商品资料及后续确认。
- **设计依据（Design Reference）：**参考的构图、版式、配色、文字层级、营销表达及场景组织可以用于再设计；不等于必须逐像素复制，也不自动取得他人素材、品牌标识或图片的使用授权。

**纠正 V0.1 的重要错误：**不能再笼统写成“所有参考图参数和卖点一律不可继承”。在 Quick-A 和经确认的 Quick-B 中，**参考的适用信息可以沿用**；真正要限制的是错误变体、未经确认的差异、他人品牌/权利内容及与目标商品不符的事实。反过来，也不能因运营选择了“看起来差不多”的图，就由模型独立宣布规格全部相同。

**业务确认与独立核验不是一回事：**“运营确认可以沿用”可作为当前制作的业务输入，但不等于已完成供应商、检测或平台合规验证。出现 SKU/型号/配置矛盾、关键数字不可辨识或授权不明时，要暴露问题并交运营决定，不靠模型补造。

### 2.2 三个工作入口的共享输入约定（E0-R01 / USER-CONFIRMED）

前端工作入口为 **Quick-A：同款快速改版、Quick-B：换主体快速改版、Listing：商品资料制图**；内部仍是 Quick / Listing 两种业务模式，Quick 下分 A/B 子场景。

三个入口应尽可能复用实际商品图上传、参考营销图上传、`product` / `reference` 角色分离、任务内共享商品素材，以及五类输出图位：`main`、`dimensions`、`comparison`、`selling_point`、`scene`。共享的图位能力包括启用状态、稳定身份、主要参考绑定、可选逐图补充要求和逐图生成尺寸；商品素材数量不自动决定输出数量。

**当前工程边界（E0 源码观察）：**已有商品/参考角色及 Quick V1 图位分类可作为复用基础，尚无完整的白底、细节、配件、包装等商品素材子分类系统。上述名称可以描述素材内容，不能写成已实现的分类能力；本次仅保留尺寸图专项规则所必需的已标注尺寸素材识别与关联需求，不扩建通用素材管理系统。三入口共享及动态 N 的工程调整仍待实施。

**共享 UI 不合并事实权限：**Quick-A / Quick-B 继续执行各自的信息沿用和主体要求；Listing 继续保留运营主动提供的商品文字资料、Planning、逐图计划及人工确认，不因采用相同图位分类而改成 Quick 直接生图。

## 3. 两种模式的最小业务流程

### 3.1 功能 A：Quick 快速生图（两种真实子场景）

共同 As-Is / 目标流程：

1. 运营上传实际商品图片，以及为目标图位挑选的参考图；必要时补充总体风格、语言、市场或逐图说明，**无需手动填写 Listing、产品描述或卖点表**。
2. 系统依据**目标商品外观**、**可沿用的参考营销信息**、**参考图设计表达**形成该图的候选成图；根据以下两个子场景决定是否必须替换参考图中的商品主体。
3. 运营检查实际商品身份、信息准确性、设计变化与制作质量；不满意则逐图修改或重生成。
4. 运营选择认可版本，Pass 并导出；生成成功不是业务验收成功。

#### 3.1.1 Quick-A：同款、同外观的再设计（`OPERATOR_CONFIRMED`）

**输入关系：**参考营销图与实际商品原图呈现的是同一款、同外观商品（实际型号/变体的一致性由业务确认；并非仅凭视觉猜测）。

**目标：**保留真实商品主体、适用的参数、卖点及其他有效营销信息，改变构图、排版、背景/风格、信息层级及必要的语言/地区表达，形成可接受的**差异化商品图**。

**必须避免：**为了追求变化而改坏商品细节、误写参数、删除重要卖点；只输出几乎未变化的参考图也可能不满足运营的差异化目标。实际允许多大设计变化及是否能直接用于某平台，仍由运营和适用规则验收。

#### 3.1.2 Quick-B：同规格、同卖点但外观不同的主体替换（`OPERATOR_CONFIRMED`）

**输入关系：**参考营销图里的商品与当前实际售卖商品**外观不同**，但运营确认其尺寸、功能/规格、卖点等本次使用的信息适用于目标商品。它们未必是完全相同的 SKU/型号，不应由视觉相似自动推定。

**目标：****必须把参考营销图中的商品主体更换成实际售卖商品原图对应的外观**，同时保留经运营确认适用的参数、卖点及有价值的设计表达，再按需要调整版式、语言与风格。

**必须避免：**保留参考图原商品主体、把两款商品的外壳/按钮/接口/标识拼合、替换主体却同时把信息错误改变、把参考包装或第三方品牌/其他变体专属事实当作目标商品内容。若参考信息与目标商品发生明确冲突，不因“同规格”口头声明而无条件忽略冲突。

**已有失败线索：**历史测试曾出现**要求更换参考图商品主体，但结果没有正确替换**的情况。这是 Quick-B 的重要回归场景；是否由输入角色、Prompt/Context 或图像模型服从能力导致，`UNKNOWN`，不能直接指定根因。

#### 3.1.3 Quick V1：共享商品素材与按图位上传参考（E0-R01 / E0-R02 同步）

**商品素材：**同一 Task 内的多个实际商品原图按已有约定属于当前目标 SKU，可能包括白底、细节、包装、配件、尺寸图；它们共同作为各图位的目标商品依据。**商品素材数量不决定输出项数量。**此约定不意味着 Quick-B 的参考商品与目标商品也必须同 SKU。

**图位与主要参考：**运营按目标图位选择是否启用。主图、尺寸图、同类对比各最多 1 项；卖点图与场景图按运营需求动态 N 项，不设置固定业务总数量上限（见 §4）。运营可动态增加、删除卖点图和场景图输出项。

- 每个启用输出项有稳定身份、明确类型、对应输出尺寸和独立生成/审核结果，并绑定一张主要参考图；未启用项不生成。同一主要参考不能绑定多个启用输出，动态 N 不改变现有绑定唯一性规则。
- 可填写逐图补充说明，不强制逐张完整 Brief；基本目标由图位类型给出。
- 第一版不引入多参考自动组合或同一参考图自动规划多个输出，不以素材张数自动增加输出项。
- **尺寸图专项例外：**没有运营提供的、已标注目标商品真实尺寸的白底素材，视为没有尺寸图需求，**不应仅因为存在某张尺寸参考图就生成尺寸图**。

**执行方式：**Quick V1 配好输入和启用图位后可以直接生成，**不执行强制独立 AI Planning**；整体要求作用于任务，逐图要求只作用于对应图位。保留原单图生成/修改、版本、Pass 和导出规则。上述属于已定业务规则，**不代表当前代码已正确区分并完成 Quick-A / Quick-B 的所有判断**。

**历史兼容：**历史 Quick 的“全局风格参考（可选）”入口保留其既有行为；Quick V1 按图位绑定主要参考，整体风格可由文本要求表达。不能把旧版历史行为当作新 Quick V1 必须具备的输入。

### 3.2 功能 B：Listing 带产品信息生图

1. 运营提交实际商品图片、参考图及**手动输入的 Listing、商品描述、卖点等商品信息**；与 Quick 的图片驱动输入有明确区别。
2. AI 前置理解产品资料与参考设计，识别可用卖点、表达方向和不确定事项，形成逐图制作建议。
3. 运营检查、确认或修改制作计划；AI 的解释不是对商品事实的独立认证。
4. 按已确认的计划逐图生成、修改、选择、Pass 和导出。

**共享输入目标：**Listing 采用 §2.2 的五类图位、启用状态、主要参考绑定、可选逐图要求及逐图尺寸，数量规则同 §4。分类信息应与原有参考/计划身份正确关联，不要求把 Listing 计划改造成 Quick 的输出 ID 体系；人工方案确认流程保持不变。

**不能自动套用 Quick 前提：**Listing 的参考图究竟是同款、同规格不同外观，还是别的产品的设计参考，此次业务澄清并未确定；参考中的参数/卖点是否能迁移，须根据该任务的商品信息与人工确认核对，不默认一律继承，也不默认一律禁止。

**共同原则：**Quick 和 Listing 的候选图片均由运营最终接受；不以模型成功调用、正确 JSON 或生成了文件代替业务合格。

## 4. V1 候选图包与特殊规则

| 图位 | 业务数量规则 | 主要目标 | 适用的资料边界 |
| --- | ---: | --- | --- |
| **主图（main）** | 最多 1 | 展示实际售卖商品 | 最终必须呈现目标商品的真实外观。Quick-B 必须替换参考商品主体；品牌/配件及平台主图要求另行核对。 |
| **尺寸图（dimensions）** | 最多 1 | 展示实际商品尺寸 | **仅当运营提供已标注真实尺寸的目标商品白底素材时制作；否则本次不生成。**不从参考版式、比例或模型推断填数。 |
| **同类商品对比图（comparison）** | 最多 1 | 表达商品差异或优势 | Quick 可沿用对目标商品成立的既有信息，但“优于其他商品”的对比对象/主张仍需证据；不凭排版虚构优势。 |
| **卖点图（selling_point）** | 按需动态 N | 突出实际可用卖点 | Quick-A / Quick-B 可沿用经确认适用的参考图卖点；Listing 依据运营提供的商品资料和确认计划。 |
| **使用/适用场景图（scene）** | 按需动态 N | 展示与商品相容的使用方式 | 场景可参考，不能暗示目标商品不具备的使用功能或效果。 |

**E0-R02 / USER-CONFIRMED：不设置新的固定业务总数量上限。**卖点图与场景图可按实际需求动态增加或删除；不要求生成全部图位。素材不足、信息冲突或运营未启用的图位可以跳过；**尺寸图未提供专项素材即表示不需要**，不应由模型主动生成或编造尺寸。

**技术保护与业务数量分开：**可以保留有依据的上传总大小、单文件大小、单次模型输入容量、Planning 输出预算、单批执行预算，以及并发、超时、费用和资源限制。这些必须明确标为技术限制，不得将旧“卖点最多 3、场景最多 2、总计最多 8”继续当作当前业务目标，也不设置替代的固定业务总数。不承诺任意 N 都能在一次 Planning 或一次批处理中完成；技术保护或分批策略须依据实际能力核验，不由本次文档同步预设。

对比图可能涉及具体竞品、自有其他型号、普通同类产品或传统使用方式；明确的优劣陈述必须与可核对依据相符。Quick 的“同卖点”不意味着所有比较结论自动成立。

## 5. 最小业务质量约束

这部分是制作底线，不等于新增全面自动合规系统。

1. **目标商品外观优先：**最终图中的商品主体由实际商品原图决定。Quick-A 保持其原貌，Quick-B **必须替换参考商品主体**；避免混合按钮、接口、颜色、外壳及专属标识。允许合理的视角/布光变化，但不能据此改变产品结构。
2. **正确沿用商品信息：**Quick-A、运营确认适用的 Quick-B 可以沿用参考营销图的尺寸、功能、卖点等内容；不得据此推断其他 SKU/变体特有内容也适用。Listing 优先使用其手动输入和确认的事实。无法辨认、矛盾或明显不适用的数字不能猜测。
3. **尺寸图专项限制：**即使 Quick 参考图已出现尺寸数字，**没有目标商品的已标注真实尺寸白底素材就不制作尺寸图**。有素材时应忠实保留其数值与对应位置。
4. **参考设计与素材权利：**借鉴风格、版式、信息组织与表达，不等于可以任意复制其他主体、他人商标、受保护图案或授权范围以外的图片资产；相同规格或商品关系不自动解决权利问题。
5. **表达与场景真实：**产品卖点、包装、随箱配件、功效/性能与使用场景须在目标商品上成立；有来源的运营声明与已经独立验证的事实应区分。
6. **渠道/地区的具体适用性：**运营可以要求视觉差异化、本地化语言与风格，但**不能笼统断言所有平台都禁止重复图片**，也不能认为“改了风格”就自动满足某平台规则。实际渠道规则需要按平台、站点、图位和当时有效规定核实；最终发布审核责任不因 AI 生成而消失。

## 6. 审核、修改、交付与业务评价

V1 保留既有的完整使用体验：同一 Task 可拥有多个候选图位；逐张检查；对不合格单图提交修改意见、重新生成或选择旧版本；运营明确 Pass 后导出认可图片，不把最新成图自动等同于已通过。

建议按**模式和子场景**观察失败，不能将三种业务条件混合计算质量：

| 场景 | 需要重点观察的失败 |
| --- | --- |
| **Quick-A** | 商品印字/结构或参数改变；适用卖点丢失；风格调整不足或与参考过度雷同。 |
| **Quick-B** | **未替换参考主体**；两款外观混合；替换后真实规格/卖点不再适用；商品细节、字样失真。 |
| **Listing** | 商品资料理解错误、未经确认事实进入计划、参考卖点误用、逐图制作方案偏离目标。 |
| **全部场景** | 布局/文字错误、质量不达标、返工过多、平台不适用、素材使用权问题。 |

持续记录商品正确性、运营接受/拒绝原因、修改次数与人力时间、每张最终可用图片的模型成本。**这些指标需要真实运营数据，当前不预设通过率或成本阈值。**技术调用成功、Mock 测试通过、某张图片 Pass 和整体商业质量，不是一回事。

## 8. 决策、纠错与未知事项

### 8.1 DECIDED / OPERATOR_CONFIRMED（经用户转述）

- **仅两种模式：**Quick（图片驱动）与 Listing（运营手动提供 Listing / 描述 / 卖点等资料）；Quick 包含 A、B 两个子场景，不拆成第三个产品。
- **Quick-A：**实际商品与参考营销图同款同外观，保留适用信息、改造视觉表达。
- **Quick-B：**参考商品与目标商品外观不同，但运营确认尺寸、规格、卖点等适用；**必须替换商品主体**，可保留适用参考信息，避免商品混合。
- 运营挑选参考图时必定参考视觉风格，通常也会考虑匹配卖点；核心表达确实不适配时，AI 默认建议换图，由运营决定，不擅自创造新卖点。
- 尺寸图专用白底素材必须已经标注目标商品真实尺寸；未提供表示不需要尺寸图。
- 三个工作入口共享基础素材角色与五类图位关系，保留各自事实权限及确认流程。Quick V1 **无强制 Planning**；卖点/场景按需动态 N，主图/尺寸/对比各 max1，无固定业务总数；保留单图修改、版本、Pass 与导出。
- Listing 继续采用运营提供的文字商品资料、AI 前置分析和人工确认；**本次未确认 Listing 参考图必须同款**。

### 8.2 OBSERVED / HISTORICAL（有时间与证据边界）

- 据 2026-10-26 Codex 只读报告，Quick V1 输入及图位相关 CP1+CP2 工程改动已存在；不能由此推断 Quick-A / Quick-B 的新业务语义已完整实现或运营合格。
- 历史测试出现过 Quick-B **应替换而未替换参考商品主体**的失败现象；具体根因与普遍发生率尚未证明。
- **2026-10-27 A/B 方案及成图实验：**共同提示词禁止沿用参考图型号、参数、包装、卖点等信息，将两组制作目标收缩为外观细节展示。**该实验的业务前提与现已澄清的 Quick 真实业务不一致**；不能用其判断 Quick 场景下 S3/S5 SOP 或 Agent 的真实增益。原始图片、请求、方案与输出仍应保留，可用于观察排版、引线及商品印字失真等局部现象，不应删改或重新标记为生产验收。

### 8.3 PROPOSED / UNKNOWN（不得伪装为已批准实现）

- 现有代码是否能区分 Quick-A 与 Quick-B 并稳定执行主体替换，**UNKNOWN**；需要按真实 Case 做业务对照。
- Quick-B 如何在仅有图片输入的条件下表达/核对“相同尺寸和卖点”这一运营断言，哪些冲突应拦截，**OPEN**；不能因缺少独立文本框就预设已经自动核实。
- Listing 参考图是否同款、同规格或不同商品，以及各类参考信息的确认权限，**UNKNOWN**。
- 不同平台对重复营销图、版权、商标、图位及本地化的具体规则，**未在本业务澄清中验证**。
- 不同 SKU 素材完整性、真实业务接受率、返工原因、合格图成本、Quick-A/B 频率与成功率，**UNKNOWN**。
- 是否为 Quick 增加独立参考理解、Knowledge、Rules、Skills、Agent，属于**下一轮能力与适配研究**，本业务基线不直接授权。
