## 0. 文档边界与使用方法

- **业务模式只有两种：** Quick（图片输入）与 Listing（运营另外提供商品文字资料）。Quick 内有 **Quick-A**（同款同外观）及 **Quick-B**（同规格／卖点、外观不同）两个子场景。
- **按场景分别梳理，再比较共性。** 本版已分别整理 Quick-A、Quick-B、Listing 的目标 Workflow，保留各自的信息来源、判断权限和确认要求，不能将 Quick 的要求自动套用到 Listing。
- **`OPERATOR_CONFIRMED / DECIDED`**：已由运营业务说明或用户确认；**`OBSERVED_CODE / HISTORICAL`**：此前有明确工程调查支持、存在证据时间边界；**`PROPOSED`**：拟议的目标 Workflow；**`UNKNOWN`**：仍需调查，不能擅自填补。
- Workflow 步骤是**业务职责和信息关系**，**不等于七次模型调用、七个服务或固定 Agent 链**，也不要求为每项活动新增人工审批；Listing 的制作计划确认和所有场景的最终图片审核仍须按各自业务规则执行。
- **历史范围说明：**第 1、2 节保留各次整理时的原文。第 2.6 节“本轮不展开 Listing／下一节待讨论”指此前 Quick-B 文档更新的范围，不是当前状态；Listing 的本次目标 Workflow 见第 3 节。

## 1. Quick-A｜同款同外观的差异化再设计

### 1.1 业务任务与交付（DECIDED）

**业务目标：**运营提供实际销售商品图片及同款同外观的营销参考图，保留真实商品外观及适用的事实／卖点，按参考的视觉设计方向重新组织构图、排版、视觉层级、风格和必要的语言／地区表达，形成供运营审核、修改与交付的差异化商品图片。

**输入：**

- 当前实际售卖商品的原始图片（同一任务内的商品素材按当前业务规则对应目标 SKU；具体变体冲突仍须核对）。
- 每个启用图位所绑定的一张主要营销参考图；Quick-A 的业务前提是参考商品与目标商品同款同外观。
- 如运营提供，则使用整体制作要求、语言／市场／渠道信息、逐图补充要求。
- **不要求**额外填写 Listing、产品描述或逐项卖点；不要求运营为每张图另写完整 Creative Brief。

**输出：**最多按照已有 V1 图位约定生成候选图，允许运营逐图修改／选版本／Pass／导出；**图片生成成功不等于运营验收通过**。

### 1.2 已确认的关键业务规则（DECIDED / OPERATOR_CONFIRMED）

1. **外观保持：**目标商品原图决定外观。不得为了视觉差异化改变真实商品的外壳、按钮、接口、颜色、结构、标识、配件关系等细节。
2. **参考信息可用，但需适用：**同款营销参考图中的商品信息、规格和卖点可以在适用于当前型号／变体、足够清楚且没有矛盾时沿用；“同外观”并不自动证明任何数字或参数都已独立核验。
3. **一定参考设计风格：**运营选择参考图时一定考虑其视觉表达，通常也已考虑卖点相同或相近；应借鉴构图、版式、信息层级和表达手法，但不要求逐像素复刻。
4. **卖点选择与突出：**若参考图有三个卖点，**允许按当前图位、整体目标只重点突出其中一两个**，无须每张图将全部卖点照搬上去；不改变被使用卖点的事实含义，**运营明确要求必须呈现的核心卖点不得未经确认擅自删除**。未成为本图重点不等于该卖点被判定为无效。
5. **参考图确实不适合时：**默认向运营说明原因并建议更换，由运营最终决定；不能仅以“设计不同”作为不适用理由。
6. **尺寸图专项：**只有运营提供**已标注目标商品真实尺寸的白底商品尺寸素材**，才存在尺寸图需求；未提供即此次不生成尺寸图，不从参考图猜测补齐。
7. **渠道及素材权利：**平台、站点、图位要求需按适用来源核实；运营希望差异化不等于存在已核实的“所有平台禁止相同图片”规则，商品同款也不自动证明参考素材拥有完整商业授权。

### 1.3 Quick-A 目标业务 Workflow（PROPOSED）

| 顺序 | 业务活动 | 谁承担／需要判断什么 | 应取得的最小结果 | 例外处理 |
| --- | --- | --- | --- | --- |
| **Q-A01** | **提交及绑定资料** | 运营上传商品图、按图位选择参考图、启用本次输出项；程序保障图位与资料关联 | 当前图位、目标商品素材、主要参考图和可选要求的明确关联 | 未启用图位不生成；缺尺寸专项素材不生成尺寸图 |
| **Q-A02** | **核对 Quick-A 前提** | 业务输入声明同款同外观；模型可提示明显的 SKU／变体／外观冲突，不能独立认证商业型号 | 明确哪些商品外观与参考信息被本次采用；已发现矛盾有记录 | 发现明显冲突时向运营确认，不自行编造新规格 |
| **Q-A03** | **理解已有营销参考图** | AI 识别参考图核心卖点、关键文字／数字、信息层级、构图与风格；区分可观察内容与推测 | 有依据的参考表达摘要、可借鉴设计手法、无法读清的信息 | 重要文本模糊或理解有歧义时不猜测 |
| **Q-A04** | **制定差异化制作决策** | AI 在运营要求和当前图位下，决定哪些适用信息保留／重点突出、怎样重新排版和表达；不擅自删除必保留卖点 | 当前图位的**可执行制作方向**：重点卖点、保留约束、拟改变的视觉要素 | 关键事实不适用、核心表达冲突或设计无法合理迁移时建议运营核对／换图 |
| **Q-A05** | **形成有效生成输入** | 程序按当前任务、素材与明确的制作决策组织实际 Context；保留输入角色、来源与版本 | 可复核的有效商品视觉依据、参考设计、文案／卖点、图位和指令 | 不把未经确认的其他变体参数或冗余历史输入混进当前请求 |
| **Q-A06** | **生成候选图片** | 复用现有图片生成能力；生成模型执行视觉再设计，不自动宣告业务合格 | 一张可供审核的候选图及对应运行记录 | 调用失败或成图失真保留证据，不擅自标记 Pass |
| **Q-A07** | **人工审核、修改、交付** | 运营判断外观、信息、设计变化、图位／渠道适用性和可用性 | 通过的版本、必要修改意见及最终导出 | 不合格逐图修改或重生；已 Pass 版本不应被最新候选静默替代 |

**执行边界：**Q-A03～Q-A05 可以合并处理；这张表**不授权 Quick 增加强制独立 Planning，也不新设每次必经的人工审批 Gate**。若现有 Quick 直接生图更合适，应在后续 AI Capability／Evaluation 中比较，而不是先把候选流程当成代码要求。

### 1.4 Quick-A 的重复业务判断与信息需求（PROPOSED）

| 判断 | 实际业务问题 | 所依赖的资料或知识 | 后续适配分析关注点 |
| --- | --- | --- | --- |
| **D1 信息适用性** | 当前参考中哪些参数与卖点可沿用，哪些版本或变体可能冲突？ | 目标商品图、同款关系、参考图片文字、运营声明 | 事实边界、可读性、异常转人工；不默认需要 Agent |
| **D2 参考表达** | 参考图用什么方法强调商品信息？ | 参考图片、图文关系、可选专业设计知识 | 以原生多模态模型为基线，重点评估理解准确性 |
| **D3 卖点取舍与差异化** | 本图突出哪一两个卖点、怎样变得不同但不失真？ | 当前图位、运营必保留要求、参考设计、设计方法 | 当前最值得研究的 S5 制作决策；Knowledge / Skills 价值待验证 |
| **D4 地区与平台适用性** | 哪些语言、渠道／图位要求实际适用？ | 已指定市场／渠道、有来源的规则、品牌要求 | 先查适用规则，不默认由模型记忆补全 |
| **D5 异常是否继续** | 发现事实矛盾、无法识别文字、参考不适用时怎么办？ | 上述依据、运营确认 | 可由规则与模型分支处理；动态查证的 Agent 价值待验证 |

### 1.5 人工责任、异常及验收（PROPOSED）

- **运营负责：**提供正确的目标商品与参考图、声明适用商品关系、给出必须保留的卖点／约束、处理关键矛盾、审核并最终 Pass。正常情况下不要求运营逐图写完整说明。
- **AI 可辅助：**解释参考图、建议卖点重点、形成差异化制作方案、提示可见矛盾与潜在风险；**不得擅自确认未知参数、品牌授权或平台合规**。
- **技术执行责任：**准确关联当前素材和图位，按授权范围调用模型，保存实际请求、结果、版本和审核证据；不把模型成功当成业务成功。

**后续验收关注：**商品外观保真、规格与卖点信息保真、运营明确必保留信息是否呈现、设计差异化的有效程度、视觉可读性／专业性、运营接受及返工次数、最终可用图片的时间和成本。暂不编造阈值。

### 1.6 已有工程基础与待验证边界

- `OBSERVED_CODE / HISTORICAL`（截至 2026-10-27 Codex 调查）：Quick V1 已有按图位绑定参考、素材与运行版本记录、直接生成、修改及人工 Pass；**Quick 不强制执行独立 Planning**。
- `UNKNOWN`：当前代码是否能够稳定落实以上 Q-A03～Q-A05 的专业制作判断及卖点取舍；是否能在不增加成本的情况下改善实际成图质量。
- `PROPOSED`：Knowledge／Rules／Skills／Agent 可作为后续适配候选，但**本 Workflow 记录不批准它们的实施**。
- `HISTORICAL EVIDENCE LIMITATION`：2026-10-27 的 A/B 实验把同款参考中的卖点与参数一律禁止沿用，违背本次 Quick 业务前提；不能据此证明真实 Quick 的 SOP／Agent 增益。原实验 Evidence 保留。

## 2. Quick-B｜换主体快速改版

### 2.1 业务任务与交付（DECIDED）

**业务目标：**参考商品与实际待售商品外观不同，但运营确认本次使用的相关规格、参数、功能和卖点适用于目标商品。以实际商品原图为最终外观依据，替换参考营销图中的商品主体，保留经确认适用的信息，并根据目标商品外形重新组织视觉设计，形成可审核、修改与交付的商品图片。业务事实源仍是 [Business Baseline V0.2 §3.1.2](V1_BUSINESS_BASELINE_V0.2.md#312-quick-b同规格同卖点但外观不同的主体替换operator_confirmed)。

**输入：**实际待售商品原图、运营选定的图位主要参考营销图、启用的目标图位，以及可选的整体或逐图制作要求；不要求额外手动填写 Listing、产品描述或卖点清单。同一 Task 的商品素材仍对应目标 SKU，素材数量不决定输出数量；图位及数量沿用 V0.2 约定。

**模式与选择：**Quick-B 是 Quick 的子场景，不是第三个独立业务模式。已确认的目标 UI 可以让运营明确选择「Quick-A：同款快速改版」「Quick-B：换主体快速改版」「Listing：商品资料制图」；三个前端选项仍对应 Quick 与 Listing 两种模式。**这是 DECIDED 的目标业务/UI 方向，不是前端已实现声明。**选择 Quick-B 表达运营对商品关系和信息适用性的声明，不等于所有参考信息已经独立验证。

**输出：**当前启用图位的候选图、可追踪的版本与运行证据，经过运营逐图审核、必要修改、指定版本 Pass 后交付；生成成功不等于主体替换完成或业务合格。

### 2.2 已确认的关键业务规则（DECIDED / OPERATOR_CONFIRMED）

1. **QB-R01｜商品外观权威：**实际待售商品原图决定最终商品外观。保持其外壳与轮廓、颜色与材质特征、按钮和接口等可见结构、实际标识与外观细节，以及已可核实的配件和连接关系；不得保留参考商品的专属外观。
2. **QB-R02｜完整主体替换：**替换范围覆盖中央主视觉、商品局部特写、结构展示、场景中的商品及其他与商品主体有关的视觉元素，均须按实际商品正确替换或调整。不得只换中央商品却留下参考商品的其他视图，也不得混合两种商品的结构。
3. **QB-R03｜信息继承：**允许沿用运营确认适用的卖点、参数、规格、尺寸、功能说明及其他营销信息；尺寸图另受 QB-R07 限制。同卖点不表示品牌、包装、配件或全部型号参数都相同；明显矛盾或不可辨认的关键信息须暴露并交运营处理，不得自行编造或消除冲突。业务确认不等于独立事实或素材权利核验。
4. **QB-R04｜卖点取舍：**与 Quick-A 共用已确认原则：参考中有多个适用卖点时，允许按本次图位和制作目标只重点突出其中部分，不机械复制全部内容；不得改变保留卖点的事实含义，或擅自删除运营明确要求保留的内容。未选为本图重点，不等于该卖点失效。
5. **QB-R05｜专业视觉再设计：**主体替换后可重新调整商品摆放与比例、视觉重心、图文位置、局部特写与引导线、信息卡和卖点排版、背景、配色与风格；不得为适配参考布局而扭曲实际商品外观。
6. **QB-R06｜参考图适用性：**外观不同是 Quick-B 的正常前提，不能据此判定参考不适用。核心卖点或使用场景确实不适用于目标商品时，默认说明原因并建议换参考，最终由运营决定，不靠模型补造商品能力。
7. **QB-R07｜尺寸图专项：**只有运营提供已经标注目标商品真实尺寸数据的白底尺寸素材，才制作对应尺寸图；没有提供表示本次不需要。不依据参考数字、图片比例或模型推测自动补齐尺寸图任务。
8. **QB-R08｜最终人工审核：**运营最终确认完整主体替换、实际商品外观、规格卖点、视觉质量、地区/渠道适用性及交付结果。模型调用或生成成功不能代替人工验收。

### 2.3 Quick-B 目标业务 Workflow（PROPOSED）

以下是目标业务活动及拟议责任分配，不是当前代码执行路径的观察记录。

| 顺序 | 业务活动 | 主要责任 | 需要完成的判断 | 应取得的最小结果 | 异常处理 |
| --- | --- | --- | --- | --- | --- |
| **Q-B01** | **选择模式与提交资料** | 运营提供资料及关系声明；程序关联图位与输入 | 是否为换主体场景，实际商品、当前主要参考及启用图位是否对应 | 明确具有 Quick-B 前提的任务、图位和可选要求 | 资料错绑交运营修正；未启用图位不生成；无尺寸专项素材不制作尺寸图 |
| **Q-B02** | **商品和参考图理解** | AI 辅助理解；运营处理商品身份和事实确认 | 目标与参考外观、可见差异、参考卖点/参数/文案及构图风格分别是什么 | 能区分目标外观、参考营销信息和设计表达的理解结果 | 关键文字不可辨认、型号或外观矛盾时不猜测，交运营核对 |
| **Q-B03** | **确定替换和继承边界** | AI 辅助整理；运营确认适用性并处理关键冲突 | 哪些视觉元素必须替换，哪些信息可沿用，哪些是参考专属或不确定内容 | 可检查的完整替换范围、信息保留要求和待确认事项 | 不将关系声明视为全部信息已核验；冲突不得静默消除 |
| **Q-B04** | **专业制作方案决策** | AI 辅助制作判断；运营提供并保留明确约束 | 本图重点卖点、必保留信息、适应新商品外形的构图/层级/特写，以及可沿用的设计风格 | 可执行的单图制作方向 | 核心表达不适用时说明原因并建议换参考，由运营决定；不扭曲商品迁就版式 |
| **Q-B05** | **Context 组织** | 程序组织有效输入；AI 辅助结果与运营确认作为依据 | 目标外观依据、当前参考、适用营销信息、替换元素、制作方向和要求是否清楚且相容 | 资料角色与约束明确的本次有效生成输入 | 不混入参考专属事实、其他图位依据或未经处理的冲突；缺失信息不由当前规则猜补 |
| **Q-B06** | **生成候选图片** | 复用现有 Generation 能力执行 | 输出是否形成可供审核的候选，运行结果能否关联本次输入 | 候选图及可追踪 Run / Evidence | 调用失败保留失败信息；生成成功不宣告主体替换正确或自动 Pass |

**输入：**实际待售商品原图、运营选择的参考营销图、运营手动提交的 Listing、商品描述/卖点等当前商品资料，以及如有的整体制作要求和逐图要求。文字商品资料是 Listing 的业务输入类别，不能将其简化为 Quick 的纯图片输入；**具体字段级必填约束沿用 V0.2，不在本文件新增每个文本框独立必填等前端限制**。图位与数量沿用既有 V1 约定，尺寸图另受 L-R07 约束。

**输出：**可供运营检查、确认或修正的逐图制作方向，随后是对应当前输入与确认版本的候选图片、Run / Evidence 和人工认可的交付版本。AI 规划、模型执行与最终运营接受分别判断。

### 3.2 已确认的关键业务规则（DECIDED / OPERATOR_CONFIRMED）

1. **L-R01｜商品外观依据：**实际待售商品原图决定最终商品主体、颜色、结构、按钮、接口及可见配置。参考中其他商品的外观不能直接冒充实际待售商品。
2. **L-R02｜商品信息依据：**运营手动提交的 Listing、产品描述、卖点及其他当前商品信息，是制作宣称的主要依据，可用于商品理解与创意规划；输入某项信息不等于该信息已得到独立技术验证。
3. **L-R03｜参考图使用边界：**参考主要提供营销表达、构图、视觉风格、信息层级、卖点呈现、场景与设计方法。额外参数、卖点或功能必须核对当前商品资料是否支持，不能自动继承全部参考信息，也不能一律否定有依据的可用信息。参考是否同款仍为 **UNKNOWN**，不得强套 Quick-A / Quick-B 的信息继承规则。
4. **L-R04｜商品资料冲突处理（本轮新增确认）：**Listing、描述或卖点与实际商品图片明显冲突时，AI 必须指出具体冲突、涉及的信息及依据边界，交运营确认；不得擅自认定文字一定正确，也不得依据图片自行改写商品事实。未解决的争议宣称不能默默升级为已确认事实并进入可执行方案。图片可能因角度、遮挡或版本差异未展示某项功能，**看不到不等于不存在，须区分明显矛盾与单纯证据不足**。此处记录本轮用户确认，不表示 V0.2 已同步改写或代码已实现。
5. **L-R05｜卖点选择与制作规划：**AI 可依据当前商品资料、运营要求、目标图位和参考表达提出逐图目标、卖点选择及制作方案，不得引入缺少依据的商品宣称。尊重运营明确要求的必要内容、风格和制作约束；进一步调整卖点优先级的权限以实际运营确认和已有规则为准，不扩大 AI 最终决定权。
6. **L-R06｜参考图不适配：**核心表达与当前商品事实或制作目标明显不匹配时，AI 应说明原因，建议运营确认或更换参考；外观不同本身不足以判定不适配。不能因为参考拥有某个卖点，就为当前商品创造相同功能。
7. **L-R07｜尺寸图专项：**仅当运营提供已经标注目标商品真实尺寸数据的白底尺寸素材，才制作尺寸图；未提供表示本次不需要。不从参考推断或复制未经核实的尺寸。
8. **L-R08｜制作方案人工确认：**商品理解、参考理解和逐图规划后，运营检查、确认或修正制作方向；AI 结果不是人工确认。存在未解决的关键事实冲突时，不能假装整个方案已满足制作条件。确认的计划须适用于当前输入版本。
9. **L-R09｜最终图片审核：**运营负责逐图审核、最终选择、Pass 和导出；生成成功、Plan 结构校验成功或模型自评成功，均不等于业务验收成功。

| **D4｜专业视觉设计与制作方法选择** | 商品外观、参考表达、确认目标、指定渠道/语言和可用设计方法 | 审核制作方向及最终可用性；确认适用要求 | 历史计划有设计方向，不能由设计字段存在证明专业可靠 | 提出布局、层级、场景、文字和方法建议并解释适用条件 | 为追求设计扭曲商品、引线错指、地区表达或方法不适用 | 可靠专业知识来源、评价标准及方法/Skills 的增量价值 |
| **D5｜信息不足、风险和异常处理** | 缺失/模糊参数、争议宣称、参考适用性、尺寸素材及运营确认 | 补充或确认资料，决定调整、暂停相关内容或更换参考 | 历史理解/计划能记录不确定性与风险；不代表所有异常已有可靠处理 | 区分缺信息与明显矛盾，提示可继续范围和需人工确认事项 | 编造数字、自动补尺寸任务、隐藏冲突或过度暂停无关内容 | 异常频率、可靠识别范围、人工处置效果及工程符合性 |
| **D6｜已确认计划与有效 Context 的一致性** | 当前输入版本、确认计划、当前图位、实际图片角色、Prompt/请求和修改记录 | 确认当前制作方向，发现偏差时修正要求并审核结果 | 历史记录有确认计划进入 Generation、版本与实际输入留存机制 | 辅助核对计划、资料角色、约束与有效请求是否一致；程序承担确定性版本校验 | 旧确认被误用、必要约束遗漏、其他图位参考混入，或把保存快照等同于远端实际接收 | 历史请求可重建程度、逐项语义一致性和远端实际执行信息 |

**研究边界：**六项是重复业务判断，不是六个 Agent 或六次模型调用；是否使用模型、规则、Knowledge、Skills、固定 Workflow 或 Agent，以及具体接口和模块，均未在本轮决定。

### 3.5 人工责任、异常及业务验收（规则 DECIDED / 目标流程 PROPOSED）

- **运营负责：**提交并维护当前商品资料、确认争议事实、提供制作要求、检查和修正计划、最终图片审核、选择版本、Pass 与交付。运营输入和确认不等于独立技术验证、素材授权或平台合规认证。
- **AI 可辅助：**理解和整理商品资料、理解参考、发现明显矛盾、说明未知、提出卖点和设计建议、形成候选制作方案；不能替运营裁定争议事实或自动接受成图。
- **程序负责：**输入角色及图位关联、版本和状态校验、实际 Context/模型请求及结果/审核记录保存。这是业务责任划分，不表示新增代码模块，也不代表本轮已验证全部行为。

| 异常 | 继续、调整、暂停或人工确认的条件 |
| --- | --- |
| **图文明显矛盾** | AI 指明冲突涉及的文字、图片和依据边界；暂停受影响的争议宣称/制作内容，交运营确认后调整，不擅自裁决哪份资料全对。仅看不到某项结构应标为证据不足。 |
| **关键参数缺失或不可辨认** | 不猜数、不当作已确认；若不影响本图必需内容，可调整为有依据的表达；本图必须使用时，交运营补充或确认后再继续相关内容。 |
| **参考含额外、不适用卖点** | 未获当前商品资料支持的宣称不直接采用；可改用有依据的信息，需保留该宣称时先核对。已证实不适用的功能不由 AI 创造。 |
| **参考核心表达不匹配** | 说明原因并建议运营确认或换参考；仅外观不同不足以拒绝。经运营处理并有适用依据后再调整制作方向。 |
| **缺少尺寸专项素材** | 不制作对应尺寸图，不从参考复制或推断尺寸；不为补齐图包自动创建尺寸任务。 |
| **Planning 与当前输入版本不一致** | 不把旧确认当作当前制作许可；按当前资料修正计划并由运营确认后再继续受影响的生成。这里描述业务完成条件，不授权自动追加付费 Planning。 |
| **成图与确认方案不一致** | 不以技术成功自动 Pass；运营依据实际成图决定逐图修改、重生或选择已有合格版本，明确通过版本后交付。 |

**业务验收关注：**商品外观及可见配置正确、参数与卖点有依据、争议事实已处理、参考借鉴和专业视觉可用、明确制作要求得到满足、当前确认与生成内容一致、最终 Pass 与导出版本一致。模型自评、结构校验或输出文件存在均不能代替运营接受；返工、时间、成本和接受率须由实际业务记录支持，不预设未批准阈值。
